# V2.2 ContextBudget 数据评审

日期：2026-08-09

状态：完成

## 实施范围

本阶段落实 Stage 1 数据评审批准的 Stage 3 第一阶段，只约束同一轮内反复重放的工具和决策上下文：

- 统一 `ContextBudget` 分配 System、State、Recent History、Decision Tool、Evidence 和 Output Reserve；
- History 与 Evidence 使用 token 计量，不再只依赖字符窗口；
- 每批工具结果向下一次决策完整展示一次，之后压缩为文档 ID、引用标签和状态回执；
- `search_rules` 仅向模型返回选择候选所需字段，移除 `structuralBlocks`、`searchBlocks` 等检索内部全文；
- 事实型问题的检索计划优先给出保守的规则条目核心名，完整自然语言问题保留为补查；
- 新增 ContextBudget 分配和压缩前后峰值的聚合指标。

未实现滚动摘要、LLM Query Rewrite、Planner、Memory 或 Multi-Agent；未改变检索器打分、候选排序、
规则正文、规则构建或 `read_rules` 来源注册边界；简单问题没有固定增加模型调用。

## 决策

本阶段满足答案质量不退化与累计 prompt 显著下降的发布门，可以独立提交。总延迟 mean 没有退化，
但 p95 单样本尾延迟上升，不作为延迟优化完成的证据。

滚动摘要继续暂缓：当前 6 轮样本的 History p95 仍只有 89 token，没有证明跨轮历史是主要成本。
下一阶段应先增加受控长会话样本并验证 library revision 变化时的状态/来源失效边界；动态 Evidence
Budget 需要依据新增意图分布单独标定，不与摘要或检索排序同时上线。
